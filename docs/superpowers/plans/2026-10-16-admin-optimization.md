# 管理後台優化實作計畫

使用者已授權依建議順序，在 `codex/admin-optimization-v2` 實作。沿用 Express、EJS、MariaDB，不提交或推送遠端。

## 順序與資料契約

1. 篩選：伺服器端處理全部資料，前端不再篩選當頁。日期須有效且起訖正確；分頁超界修正；日期快捷使用伺服器時區。
2. 還原：明確區分完整還原與匯入單一使用者。完整還原依名稱匹配，缺少者新增，來源 ID 映射至目的 ID；不覆寫既有資料；同使用者、時間、血壓與心跳相同者略過。預覽與確認使用同一檔案並在交易內重新檢查。
3. 操作紀錄：新增 `admin_audit_logs` 與 `backup_logs`、升級 SQL、登入保護的紀錄及系統狀態頁。記錄操作帳號、類型、對象、筆數、結果與原因。備份狀態代表伺服器產生匯出，不能代表使用者已保存檔案。
4. 記錄管理：單筆編輯、刪除與最多 100 筆批次刪除；要求原因；交易內寫入稽核，失敗回復。編輯使用明確時區的時間值；不改變使用者歸屬。最後管理修改資訊取自稽核。
5. 總覽：近期異常連結、未量測提醒、資料完整性狀態、最近備份。沿用既有手機卡片，加上狀態文字、可操作按鈕與對話框焦點管理。
6. 相容性：保留 SQL 下載，明示舊版用途；舊 SQL 匯入不新增使用入口。記錄 JSON 檔案大小與還原筆數限制。

## 檔案與驗證

- `lib/admin-records.js`：篩選及編輯驗證；`test/adminRecords.test.js` 驗證日期、互斥狀態及數值邊界。
- `lib/backup.js`、`lib/admin-import.js`：來源資料驗證、使用者映射、去重與交易；`test/backup.test.js`、`test/adminManagement.test.js` 驗證重複匯入及回復。
- `lib/admin-audit.js`、`routes/admin-management.js`：稽核、備份狀態及記錄管理；整合測試驗證認證、CSRF、找不到資料、修改與刪除。
- `routes/admin.js`：接入篩選、還原、稽核與持久備份。
- `views/admin*.ejs`、`public/admin.js`、`public/admin.css`：頁面與互動；HTTP 渲染、DOM 行為測試與瀏覽器桌面／手機檢查。
- `mariadb/migration-003-admin-management.sql`、初始化 schema、`README.md`：升級說明。

測試先確認新增契約缺失，再實作，最終執行 `npm test`、`node --check` 與 `git diff --check`。不連線或修改 `.env` 指向的資料庫；資料庫交易使用隔離測試替身，若有本機可用的獨立 MariaDB 再作真實 SQL 驗證。
