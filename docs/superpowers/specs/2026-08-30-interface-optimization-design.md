# 全站介面初步優化設計規格

## 目標

在不改變既有功能、資料格式與主要操作流程的前提下，優化血壓記錄系統在手機與 PC 上的可讀性與操作清晰度。範圍包含先前確認的「首頁初步優化」及「全站文字對比度優化」。

## 使用情境

- 手機：長輩以觸控選擇使用者並開始量測，需快速辨識頁面目的、使用者名稱與主要入口。
- PC：家人或照顧者使用較寬螢幕查看入口與摘要，需善用空間但維持簡潔。
- 所有裝置：主要文字需具足夠對比度，輔助文字不能因過淡而難以閱讀。

## 設計原則

1. 保留既有綠色健康主題（`#2d6a4f`、`#40916c`）及血壓狀態色彩。
2. 保留現有長輩友善的大字體、大按鈕與單純操作流程。
3. 手機維持單欄與清楚的觸控目標；PC 可利用寬度呈現額外摘要，但不將手機版複雜化。
4. 不新增資料庫欄位、不改變既有 URL、不改變血壓輸入流程。
5. 文字對比度調整只提高可讀性，不改變狀態顏色的語意。

## 首頁優化

修改 `views/portal.ejs` 與必要的共用樣式：

### 手機

- 頁面上方統一顯示「血壓記錄管理系統」。
- 不顯示「今天 X 月 XX 日」日期資訊。
- 使用者選擇區明確顯示「選擇使用者」標題。
- 每張使用者卡片保留完整姓名，並加入「點擊開始」輔助提示。
- 使用者姓名使用深黑藍 `#1a1a2e`，不得使用過淡灰色。
- 保留管理入口；入口需有清楚的管理語意，不依賴日期資訊。
- 加入簡短提示：「每日早晚各量一次，記錄更完整」。

### PC

- 頁首統一顯示「血壓記錄管理系統」，不顯示日期。
- 使用雙區塊布局：左側歡迎／開始記錄區，右側使用者選擇區。
- 使用者姓名使用 `#1a1a2e`。
- 可在入口頁提供最多三項摘要資訊：今日記錄、本週平均、最近狀態；若目前後端沒有這些資料，不得捏造數據，應以實際資料計算或暫不加入摘要。
- 保持主要操作為選擇使用者，不新增額外步驟。

## 全站文字對比度

在 `public/styles.css` 及必要的 EJS 內嵌樣式中，統一調整低對比文字：

| 用途 | 目標色彩 |
|------|----------|
| 主要標題與使用者姓名 | `#1a1a2e` |
| 一般文字與欄位標籤 | `#444`～`#555` |
| 輔助文字、日期、統計說明 | `#666` |
| 正常／高血壓／低血壓狀態文字 | 保留既有語意色彩 |

不得把主要內容改成低對比灰色；不得把血壓狀態色彩全部改成黑白。

## 元件與檔案邊界

- `views/portal.ejs`：首頁文案、首頁布局與使用者卡片呈現。
- `public/styles.css`：跨頁共用文字、按鈕、卡片與響應式樣式。
- `views/index.ejs`、`views/records.ejs`、`views/stats.ejs`、`views/modify.ejs`、`views/admin.ejs`、`views/admin-login.ejs`：只在確有低對比文字時調整顏色；不做無關版面重構。
- 不修改 `routes/`、資料庫 schema、API 契約或認證邏輯。

## 響應式要求

- 手機寬度（≤480px）下，使用者姓名、提示與按鈕不得溢出或被截斷。
- PC 寬度下，內容維持可讀的最大寬度，不因新增區塊造成過度分散。
- 所有可點擊的使用者卡片與管理入口保留現有觸控尺寸。
- 頁面在手機與 PC 均可透過鍵盤 focus 或滑鼠／觸控操作。

## 測試與驗收

### 靜態驗收

- 所有受影響 EJS 可由 EJS compiler 成功編譯。
- 內嵌 JavaScript 維持可解析。
- `git diff --check` 通過。
- 不存在「今天 X 月 XX 日」首頁文案。
- 使用者姓名的有效 CSS 顏色為 `#1a1a2e`，且未被更具體的低對比規則覆蓋。

### 手動驗收

在手機寬度與 PC 寬度檢查：

1. 首頁標題清楚顯示「血壓記錄管理系統」。
2. 使用者姓名能清楚閱讀，並顯示「點擊開始」。
3. 點擊使用者後仍能進入原有血壓輸入頁。
4. 管理入口仍能進入 `/admin`。
5. 記錄、統計、輸入、修改及管理頁的低對比文字較原本清楚。
6. 血壓狀態顏色仍能區分正常、高血壓及低血壓。

### 範圍限制

本次不加入完整儀表板、不重做圖表、不改變資料庫查詢、不新增深色模式、不加入新的互動流程。
